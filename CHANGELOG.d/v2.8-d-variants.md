### Added — guest layout variants, gallery and end-to-end matrix (bundle D)

- Three new guest shells beside the default split: `CenteredLayout`,
  `CoverLayout` and `CardLayout` in `resources/js/Layouts/Guest/`. Each is
  responsive, theme-aware, keyboard-safe and mounts from a local structural copy
  of the appearance payload, so none of them imports the engine.
- `normalizeAuth()` / `normalizeSurface()` in `resources/js/Layouts/Guest/authTypes.ts`:
  a total client-side normaliser. A missing, null, string, numeric or half-built
  payload becomes the stock split-on-brand shape rather than a broken shell.
- **Demo → Guest layouts** (`/admin/demo/auth-layouts`): every shell in the build
  at quarter scale, light and dark, over every background the server can resolve.
  Previews are real `Background` payloads from `AppearanceManager::fromInput()`,
  so the gallery cannot drift from the login page.
- `docs/admin-framework/appearance.md` — the appearance guide.
- `tests/Feature/Appearance/AuthMatrixTest.php` — seven guest routes crossed with
  four layouts and six background types, three of them against an authenticated
  actor, plus structural guards on every shell in `Layouts/Guest/`.
- `tests/js/authShells.spec.ts` — mounting, slot rendering, card isolation, image
  `@error` fallback, decorative markup and focus order for all three shells.

### Notes

- The shells contain **no** `onErrorCaptured`. Their decorative layer is made of
  intrinsic elements only and cannot throw, and a handler placed on the shell
  would also swallow errors raised inside the form slot — the one place an
  error must never be hidden.
- The 5.3 surface style object is factored into `surfaceStyle()` in
  bundle D's own `authTypes.ts` rather than retyped three times. It is a plain
  function in D's bundle, not a shared Vue child, so no cross-bundle component
  import is introduced.
