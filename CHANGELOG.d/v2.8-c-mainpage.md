### Main-page surface (bundle C)

**Added**

- `resources/js/Pages/Public/Templates/_shared/SiteSurface.vue` — one wrapper that owns
  what sits behind the navbar, the sections and the footer. All six templates
  (`Classic`, `Minimal`, `SaaS`, `Editorial`, `Docs`, `Spotlight`) now wrap their chrome
  in it, and the `make:myra-landing` stub scaffolds new templates the same way.
- `app/Homepage/PageSurfaceFallback.php` — the inert `type: 'none'` payload the homepage
  ships when the appearance engine is absent, disabled or throwing.
- `HomepageController` emits `surface` and `navbarTranslucent`. Both resolve the engine
  optionally (`class_exists` plus a `try`), so the public homepage can never fail because
  of an appearance setting.
- `SiteNavbar` takes `translucent`. Off by default; on, it drops its own panel so the
  surface runs to the top of the page. The mobile dropdown stays opaque chrome.
- A background card on `Admin/Landing/Index.vue`, writing the five `page_*` rows on the
  `appearance` settings group and dropping the brand cache.
- `appearancePage.*` locale keys, en/ms/zh at full parity.

**Guarantees**

- Nothing changes on upgrade: `page_bg_type` defaults to `none`, and `SiteSurface` then
  renders exactly `<div class="min-h-screen bg-background text-foreground">` and no other
  node. `tests/js/siteSurface.spec.ts` asserts the class string and the child count.
- One implementation for both render paths. The surface sits on the template root, above
  the legacy/page-builder branch inside `TemplateBody`, so `blocks === []` and
  `blocks !== []` receive the identical payload — asserted in
  `tests/Feature/Homepage/PageSurfaceParityTest.php`.
- Contrast: the foreground is SERVER-computed and inherited from the root, the media
  layers render only when the server supplied both `--myra-page-bg` and `--myra-page-fg`,
  an image that 404s hides itself and leaves the base colour, and the image scrim
  defaults to 0.55 when the server sent none.
- Authored values: the type, recipe and scrim are allowlisted server-side and again in the
  client normaliser; the colour must be `#rrggbb`; only `--myra-page-*` custom properties
  survive, with the same character allowlist `BrandManager::styleTag()` uses; the image URL
  goes through `safeSrc()`. No `v-html`, no raw interpolation, no authored CSS.
- `page_bg_image_path` is never accepted by the landing form — uploads are the only way an
  image path is ever stored.

**Known seam (post-merge follow-up)**

- `SiteFooter.vue` keeps `bg-muted/30` and `text-muted-foreground`, which are measured
  against the THEME background rather than the surface. It is not this bundle's file; give
  it the same treatment `SiteNavbar` got.
